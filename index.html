等待点击「混淆」

右侧产物由编译期 21 项 AST 变换生成：字符串全部落成 XOR 密文常量（strings/grep 抓不到明文）、 方法名替换为 _fn_ + 高熵随机串、控制流被压平成 match 状态机调度、条件里塞入依赖运行时的恒真谓词、 int 常量被包装成会自我还原的类型黑洞 _I(...)、异常抛出点改成暗语表 _ERRxxx(code, cls, *args)。 类名、参数名、魔术方法、@dataclass 字段访问均被豁免引擎保护，函数签名与对外 API 一字未动，行为完全等价。 改动输入框内容后再次点击「混淆」，会得到浏览器内的简化风格演示（非真实产物）。

// techniques

混淆手段全览

四层落地，43 项手段。每一项都标注了实现函数、作用解析与当前状态——包括那些「已经写进去但暂时空转」的部分。

01

编译期：AST 变换

21 项

标识符熵化重命名

生效
_gen_entropy_name

函数/方法名 → _fn_ + 高熵随机串（长度可调 4–32）。类名、参数名、魔术方法、test_* 一律不改。还会丢弃含 frida/pydev/ida/x64dbg 等子串的随机名——防止混淆结果意外撞上自己的沙箱检测名单。

跨模块重命名同步

生效
visit_ImportFrom / visit_Import / visit_Attribute

from pkg.mod import fn、from pkg import mod、import a.b 三种形态全部登记，调用点同步改写。否则跨模块调用直接断链。

作用域遮蔽保护

生效
_collect_scope_bindings

裸名重命名不区分作用域时，与「方法同名」的形参/局部变量会被误改（ast.arg 却不变）→ UnboundLocalError。这里维护作用域栈规避。

内置属性名保护

生效
BUILTIN_ATTR_NAMES

约 200 个内置/标准库属性名（to_bytes/encode/split/exists…）不作方法重命名位置。因为属性改写不做接收者类型推断，否则 (5).to_bytes(...) 会被一起改坏。

协议方法保护

生效
is_protocol_method

visit_* / generic_visit 不改名。ast.NodeVisitor.visit() 用 getattr(self, "visit_"+NodeType) 按字面名分发，改名后整条遍历会静默退化。

栈上瞬态字符串

生效
_build_stack_string / _build_stack_decoder_function

每个字符串用不同密钥 XOR（密钥取 128–254，密文必为非 ASCII，strings/grep 抓不到），运行时在 ctypes.create_string_buffer 里解码，解完立即 memset 清零。防静态字符串提取 + 防内存 dump 残留。

字符串拆分（5 算法池）

生效
_split_string → join / base64 / reduce / 奇偶位 / bytes 重建

破坏字符串的语法形状（常量 → 表达式），值不变。base64/functools 用内联 __import__，不依赖目标模块是否导入。

类型黑洞

生效
_build_type_wrapper_class / _wrap_constant_in_type_hole

int 常量包成 int 子类 _I(...)：重载 + - * / // 并保持结果仍是该类型、__repr__ 还原成普通整数；构造时还翻转 builtins 上一个幽灵标志位。只包 int（float 会被截断）。

MBA 混合布尔算术

生效
_apply_mba / _build_guarded_mba

a+b → (a^b)+2(a&b)、a-b → (a^b)-2((~a)&b)、a^b → (a|b)-(a&b)。关键在运行时 int 类型守卫：两侧都是 int 才走 MBA，否则回退原运算（否则 str/list 位运算直接崩）。操作数绑到 lambda 形参，只求值一次。

活体死代码

生效
_inject_living_dead_binop

MBA 外再套 (lambda t1,t2: t1)(expr, None)，注入无副作用的假参数，让伪造运算真正进入数据流（不是不可达代码，反编译器无法当死代码删掉）。

不透明谓词（DSV）

生效
_build_opaque_predicate

4 种数学恒真式轮换，全部依赖运行时状态：id(None)²+time_ns()≥0、(randbits(16)|1)>0、len(md5(b'').digest())>0、((id(None)|1)&1)==1。以 原条件 and 谓词 合入 if/while——静态分析折不出常量。

控制流平坦化（函数级）

生效
_flatten_to_dispatcher

按基本块切分 → while True: match 状态码 调度机，末块状态置 0 退出；额外塞一个永不命中的假 case（id(None)^id(0)）。只对块数 >2 的函数生效。

控制流平坦化（模块级）

生效
_wrap_top_level_stmts

把模块级连续可执行语句打包成状态机，循环条件再 and 一个恒真谓词。有两条硬约束：必须就地替换（否则与函数定义交换执行顺序会改变输出）、只装箱「引用名此刻已绑定」的语句（否则 NameError）。

恒定时间比较

生效
_build_constant_time_compare

a == b / a != b → hmac.compare_digest(str(a).encode(), str(b).encode())，消除 == 的短路时序侧信道（!= 再套一层 not）。

异常路径改写

生效
_build_exception_encryption / visit_Raise

raise ValueError("msg") → raise _ERRxxx(<随机码>, ValueError, "msg")：把抛出点做成暗语，异常类与原参数原样透传（保 except 语义与消息文本）。_code / _ERR_MAP 是干扰诱饵。

幽灵死代码

生效
_build_ghost_dead_code

模块级 _ghost_xxx = lambda: [id(None)^md5(...), rand&rand]。惰性赋值，热路径零开销，污染模块符号表。

match / f-string 保护

生效
visit_Match / visit_JoinedStr

match 只变换 subject/guard/body，pattern 保持原样（字面量被包成 Call 会被 Python 当类模式 → TypeError）；f-string 内部字面量不加密（Call 节点会污染 JoinedStr）。

多策略元类注入

生效
_build_metaclass → 6 策略池

给类挂 __getattribute__ 钩子：调用方函数名前缀命中「安全前缀池」（__init__/_make/_validate/from_orm/_sa_…）时还原被换掉的 __dict__，否则按 _obfmap_ 反查。目的是兼容 ORM/dataclass 的字段访问，同时对外隐藏真实属性名。6 种结构完全不同（inspect / sys._getframe / __import__ 延迟 / 极简 / 闭包链 / 装饰器注入），消除 YARA 式全域指纹。

兼容类属性映射

生效
_build_compat_obf_map

给 dataclass/ORM 风格类生成 _obfmap_ 字典与 _safe_xxx(self, name, value)，字段名随机化后再映射回原名。

污点重写（动态属性）

条件
analyze_dynamic_access / _build_secured_getattr_call

检测到 getattr(obj, 变量名) 就改写成 _sg_xxx(obj, name, md5摘要)，在 AttributeError 时联动蜜罐。绝不阻断构建。只重写 2 参数形式（3 参数的默认值会被丢）。

元类冲突规避

生效
_inject_metaclass

外部基类（ast.NodeVisitor、abc.ABC、enum.Enum）或已注入元类的本地基类不再注入，避免 metaclass conflict；不重复加 @dataclass；明确不做 __slots__ 名字随机化（历史上导致 AttributeError）。

02

运行期：一次性初始化（import 时执行）

10 项

API 去特征化

生效
_build_api_stealth

解析 /proc/self/maps 找到 libc 的 r-xp 段，用 CFUNCTYPE 造函数指针直接调 prctl(PR_SET_DUMPABLE)；Windows 走 SetProcessWorkingSetSize，macOS 走 ptrace(PT_DENY_ATTACH)。所有检测字符串（r-xp/libc/linux/win32）先 SHA-256 哈希再比对，静态扫不到明文。中间夹 _smoke_syscall() 做调用序列烟雾。

反内存 Dump（平台自适应）

生效
_build_core_dump_prevention

Linux: prctl + setrlimit(RLIMIT_CORE, 0)；Windows: 收缩工作集；macOS: ptrace。三个平台分支用哈希比对选路，无硬编码特征。

环境综合检测入口

生效
_build_vm_environment_check

组合下面 4 个探测函数，任一为真就 time.sleep(1000) 秒后 sys.exit(0xDEAD)——睡眠拖延而非直接退出，提高动态分析成本。

├ 反 VM 检测

生效
_build_vm_cpu_detection

网卡 OUI 前缀（VMware/VirtualBox/QEMU/Hyper-V 6 个）+ /proc/cpuinfo 关键词 + platform.processor() 是否含 hypervisor；全部 SHA-256 截断哈希比对，零明文。

├ 沙箱进程检测

条件
_build_sandbox_process_detection

用 psutil.process_iter 扫进程名，对照 17 个分析工具哈希表（procmon/wireshark/ida/x64dbg/fiddler…）。psutil 不在则静默跳过。

├ 低资源检测

条件
_build_low_resource_detection

内存 < 4 GB 或 CPU < 2 核视为沙箱。误报风险高（低配真机/容器会被判定）。

├ 时序异常检测

条件
_build_timing_anomaly_detection

sum(range(1000)) 耗时 < 1000 ns 判定为异常快（虚拟化/仿真）。阈值写死，同样易误报。

文件完整性校验

生效
_build_file_integrity_check

编译期把源文件 SHA-256 硬编码进产物，运行时重算比对；不符则联动蜜罐 + raise RuntimeError('FILE_TAMPERED')（注意：异常被外层 except 吞掉）。

导入期自变异

生效 · 空行为
_build_import_morphing_loader

往 sys.meta_path 头部插一个自定义 finder，种子 = pid ^ time_ns()。目前 find_module 恒返回 None，实际是占位 hooks + 污染 meta_path（未来接入真实变异）。

防御序列随机化

空转
_build_shuffled_guard

生成 5–15 轮 os.getpid() 循环的守卫函数，打乱调用序列特征。

03

运行期：后台守护线程

7 项

多因子完整性链

生效
_build_bytecode_integrity_stub

每个模块级函数首行插 _register_critical(fn) 记录 co_code 哈希；后台线程每 20–35 秒重算。任一不符 → _OBF_INTEGRITY = False。_safe_decrypt 在熔断时返回 os.urandom（密钥自动作废）。熔断已就位，后果尚未接线。

C 级内存校验

生效
_build_clvl_integrity

用 ctypes.string_at(ptr, size) 直接对原始内存做 SHA-256，绕过 Python 层 hook。种子 = pid ^ time_ms ^ id(os)，后台每 15–35 秒巡检。

内存页重随机化

生效 · 空循环
_build_memory_randomizer

用 mmap + madvise(MADV_DONTDUMP) 分配匿名页，后台线程每 5–15 秒把数据搬到新页并 memset 旧页，对抗内存扫描。当前 _MEMORY_PAGES 恒为空 → 线程空循环。

后台沙箱复检

生效
_build_background_guardian

每 30–47 秒复检 CPU 核数与内存总量，命中则联动蜜罐。睡眠间隔掺入 id(thread) % 17 抖动，避免固定周期被识别。

栈帧返回地址加密

生效
_build_stack_frame_encryption

用 sys.setprofile 挂钩，在 call/return 事件里把 frame.f_lasti 与 id(frame) 异或。目的是污染 sys.setprofile 钩子存在性（运行时自检里「sys.setprofile 钩子存在」就是它）。

蜜罐响应

条件
honeypot.py

trigger_compromise() 后 apply_noise 每次把噪音级别 ×1.5（上限 1.0），按比例随机翻转字节位/替换可打印字符——输出渐进污染。另有假数据包、假 quote、RTC 时间炸弹（时间回跳 > 阈值即触发）。

反调试引擎

部分生效
anti_debug.py

IsDebuggerPresent（Win）/ TracerPid（Linux）、RDTSC 时序抖动、MAC 前缀 OUI、DMI 系统串。注意：_detect_hw_breakpoints() 与 forge_stack_frame() 是空实现，CPUID vendor 检测也直接 return False。

04

分发期与工程侧

7 项

文件封印

生效
seal_file / body_digest

尾部追加 #@AO-SEAL-v1:<Ed25519签名>:<SHA-256摘要>，签名覆盖「去掉尾标的正文」。纯 Python 实现 Ed25519（RFC 8032），无第三方依赖。

加密二进制授权

生效
encrypt_license

magic(8)|salt(16)|nonce(16)|密文|tag(32)；HKDF-SHA256 派生密钥（ikm 含机器码），HMAC-SHA256 计数器模式流加密，encrypt-then-MAC。密文与机器码强绑定。

机器指纹（HWID）

生效
machine_fingerprint

SHA-256(系统 + 架构 + uuid.getnode() + 主机名 + PROCESSOR_IDENTIFIER + COMPUTERNAME + 用户名)。

首次运行计时

生效
first_run_timestamp

授权只存 days，到期 = first_run + days×86400。状态文件加密且绑机器码，多副本取最早。

分片乱序分发

生效
split_bundle.py

按顶层定义边界 + 行/字符级细分，切成数百片（每片 ≤4096 B），随机命名、顺序打乱，入口持内置顺序表文本拼接后 exec。分片本身无需是合法 Python。

豁免引擎（护栏）

生效
exclude_engine.py

13 种规则：decorator / inheritance / dataclass / protobuf_message / magic_methods / function_regex / path_regex / enforce_slots / build_abort / compat_inheritance… + @preserve 装饰器。这是防止把框架改坏的安全阀，不是混淆手段。

pipeline.py

Phase1 解析+slots+污点 → Phase2 AST 混淆 → Phase3 Cython → Phase4 LLVM -fla → Phase5 PGO 双编 → Phase6 SMC/懒加载互斥 → Phase7 CI 熔断。Phase3–5 为可选加速轨道。
